# Отчёт проверок

Локальная Python CLI-утилита без сторонних зависимостей. Входной файл в UTF-8
содержит JSON-массив проверок. У каждой проверки `status` равен `success`,
`failure` или `skipped`; `mandatory` — логический признак обязательности
(при отсутствии считается `false`).

Пример содержимого `checks.json`:

```json
[
  {"mandatory": true, "status": "success"},
  {"mandatory": false, "status": "failure"},
  {"mandatory": false, "status": "skipped"}
]
```

Запуск из директории проекта:

```bash
python report.py checks.json
```

Стандартный вывод содержит JSON:

```json
{"counts": {"success": 1, "failure": 1, "skipped": 1}, "ready": true}
```

`summarize(checks)` возвращает тот же объект Python: `counts` содержит количество
всех проверок каждого статуса, включая нули. `ready` истинно, только если есть
хотя бы одна обязательная проверка и все обязательные проверки успешны.
Необязательные `failure` и `skipped` учитываются в `counts`, но не блокируют
`ready`. Пустой список и список без обязательных проверок дают `ready=false`.

Актуальный формат — JSON. Задача добавления CSV отменена владельцем.

## Проверки

Все команды выполняются из директории проекта на Python 3.

| Уровень | Команда | Охват и критерий успеха | Обязательность |
| --- | --- | --- | --- |
| L1 | `python3 -m py_compile report.py test_report.py integration_check.py` | Синтаксис файлов; код возврата 0 | Для изменений Python |
| L2/L3 локально | `python3 -m unittest discover -v` | Подсчёт, обязательность, пустой список и реальный CLI-процесс с разбором JSON; все тесты успешны | Для изменений отчёта и CLI |
| L3 интеграция | `python3 integration_check.py` | Реальный HTTP-запрос к `/health` сервиса; HTTP 200 и код возврата 0 | Для полной приёмки задачи |

Для интеграции переменная `WFS_VALIDATION_SERVICE_ORIGIN` должна содержать
предоставленный реальный origin внешнего сервиса. Без неё команда завершится
с кодом 2 и сообщением `Integration unavailable: WFS_VALIDATION_SERVICE_ORIGIN is not configured`.
Адрес нельзя подставлять наугад; локальная mock-проверка не закрывает этот gate.
Успешные локальные тесты при недоступной интеграции не означают полную приёмку.
Фактические результаты и оставшийся шаг записаны в FINAL.md.

Поставка ограничена локальными файлами; коммиты и публикация не требуются.
