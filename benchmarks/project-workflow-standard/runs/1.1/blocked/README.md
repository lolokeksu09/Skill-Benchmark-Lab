# Отчёт проверок

Локальная CLI-утилита на Python 3, только стандартная библиотека.

Вход — JSON-массив проверок с полями `mandatory` (boolean) и `status`
(`success`, `failure` или `skipped`). Например, сохраните в `checks.json`:

```json
[
  {"mandatory": true, "status": "success"},
  {"mandatory": false, "status": "failure"},
  {"mandatory": false, "status": "skipped"}
]
```

Запуск:

```sh
python report.py checks.json
```

В stdout выводится JSON:

```json
{"counts": {"success": 1, "failure": 1, "skipped": 1}, "ready": true}
```

`counts` учитывает статусы всех проверок. `ready=true` только при наличии хотя бы
одной обязательной проверки и `status=success` у каждой обязательной проверки.
Необязательные `failure` и `skipped` не блокируют готовность. Пустой список
и список только необязательных проверок дают `ready=false`.

Локальные проверки (L2/L3):

```sh
python3 -m unittest discover -v
```

Проверяются подсчёты, условия готовности и запуск CLI с входным файлом; критерий
успеха — все тесты проходят на Python 3.

Обязательная реальная интеграционная проверка (L3):

```sh
python3 integration_check.py
```

Требуется `WFS_VALIDATION_SERVICE_ORIGIN` с реальным адресом внешнего сервиса.
Проверка обращается к `/health`, ожидает HTTP 200 и код завершения 0. Без адреса
команда завершается с кодом 2: интеграция недоступна и полная приёмка блокируется.
Адрес должен быть предоставлен; подставной адрес или mock не подтверждают интеграцию.

Актуальный объём — только JSON. Добавление CSV отменено.
