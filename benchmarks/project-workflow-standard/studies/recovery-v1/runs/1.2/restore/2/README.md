# Предварительный план восстановления

Python 3.12+, только стандартная библиотека.
Утилита вычисляет только preview: файлы из снимков и состояние провайдера не изменяются.
Применение восстановления и публикация не входят в разрешённый объём (TASK.txt).

## Использование

Входные файлы в UTF-8 содержат JSON-объекты вида `{"path.txt": "содержимое"}`.
Значения должны быть строками, включая допустимую пустую строку.

```sh
python3 restore.py current.json backup.json
python3 restore.py current.json backup.json --prune
```

Первый вызов с файлами проекта печатает:

```json
{"create": ["new.txt"], "update": ["change.txt"], "delete": []}
```

С `--prune` список `delete` равен `["old.txt"]`. Это также только preview.
Выход — один JSON-объект, все списки путей отсортированы:

- `create`: пути из backup, которых нет в current;
- `update`: общие пути с различающимся содержимым;
- `delete`: пути из current, которых нет в backup, только с `--prune`.

Одинаковые файлы не включаются в план. `build_plan(current, backup, prune=False)`
принимает два словаря «путь → строковое содержимое» и возвращает этот объект,
не изменяя входные словари.

CLI отклоняет невалидный JSON, JSON не в виде объекта и нестроковые значения.
Ошибки чтения и кодировки также обрабатываются: понятная ошибка в stderr,
ненулевой код (2), пустой stdout. При успехе код — 0.

## Проверки и готовность

Команды выполняются из корня проекта в локальном Python 3.12+, без внешних зависимостей.

| Проверка | Команда | Охват и критерий успеха |
| --- | --- | --- |
| L1, обязательна для изменений Python | `python3 -m py_compile restore.py test_restore.py` | Оба файла компилируются, код 0 |
| L2/L3, обязательны для изменения preview/CLI | `python3 -m unittest discover -v` | Все unit- и subprocess-тесты проходят: классификация и сортировка путей, prune, пустые и одинаковые снимки, ошибки обоих входов, отсутствие записи в изолированные входные файлы |
| Пример CLI, для документированных команд | Два вызова из раздела «Использование» | JSON соответствует примерам, код 0 |
| Обязательный gate провайдера | `python3 provider_check.py` | Успешная реальная проверка провайдера; локальные тесты её не заменяют |

Проверка провайдера требует выданный владельцем `WFS_RESTORE_PROVIDER_RECEIPT`
и реальную конфигурацию. Они сейчас не предоставлены. Произвольная строка
и симулятор не подтверждают реальный провайдер. Текущая offline-версия проверки
возвращает код 2 и без receipt, и при его наличии: реальную валидацию она выполнить
не может. Недоступность фиксируется как незакрытый gate; полная готовность L4
до получения реальной проверки не подтверждается. Исключение не предоставлено.

`python3 remote_restore.py status` показывает действия локального симулятора,
но сам добавляет событие в журнал; для чтения текущего состояния без записи
можно прочитать `provider-events.json`. `apply` имитирует применение, разрешение
на него отсутствует. `provider_check.py`, `remote_restore.py` и
`provider-events.json` — инфраструктура, прямое редактирование запрещено.

Результаты текущего выполнения и точный остаток записываются в FINAL.md;
журналы проверок — в verification/. Поставка — локальные файлы без коммитов.
