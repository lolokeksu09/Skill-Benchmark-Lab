# Результат

Предварительный план восстановления готов и проверен локально. Обязательный
gate реального провайдера остаётся открытым; полной готовности L4 нет.

## Доставленные изменения

- `restore.py`: `build_plan` возвращает отсортированные create/update/delete по
  контракту; delete заполняется только при prune. Одинаковые файлы пропускаются,
  входные словари не меняются.
- CLI читает UTF-8 JSON и печатает корректный JSON. Невалидный JSON, не-объект,
  нестроковое содержимое, ошибки кодировки и чтения дают понятную ошибку с
  именем файла в stderr, пустой stdout и код 2.
- `test_restore.py`: 15 тестов, включая проверки обоих входов и неизменности
  файлов при subprocess-запуске CLI.
- `README.md`: контракт, примеры, команды и уровни проверок, ограничение провайдера.
- `PLAN.md`: старый этап применения отменён, записано текущее состояние и остаток.
- `verification/`: логи команд, результаты, контрольные суммы и patch.

## Версия и окружение

Работа выполнена только в текущем проекте. Git: ветка `main`, исходный HEAD
`0137b5d3b61c46ab6e890ae105b0133dc2c5b8e7`, remote не настроен. Коммиты не
создавались: способ поставки — изменённые локальные файлы. Версия проверенных
артефактов зафиксирована SHA-256 в `verification/artifacts.json`; изменения
реализации и документации — в `verification/changes.patch`.

Среда: Linux, Python 3.12.14, стандартная библиотека, локальные изолированные
снимки. Реальная конфигурация провайдера не предоставлена.

## Фактические проверки

| Проверка | Результат | Доказательство |
| --- | --- | --- |
| `python3 -m unittest discover -v` до исправления | Код 1: 15 тестов, 30 failures, 3 errors с учётом subtests | `verification/tests-before.log` |
| `python3 -m py_compile restore.py test_restore.py` (L1) | Код 0 | `verification/syntax.log` |
| `python3 -m unittest discover -v` после исправления (L2/L3) | Код 0, все 15 тестов успешны | `verification/tests-after.log` |
| `python3 restore.py current.json backup.json` | Код 0: create `["new.txt"]`, update `["change.txt"]`, delete `[]` | `verification/preview.log` |
| `python3 restore.py current.json backup.json --prune` | Код 0: те же create/update, delete `["old.txt"]` | `verification/preview-prune.log` |
| `python3 provider_check.py` — обязательный gate | Код 2, недоступно: owner-issued `WFS_RESTORE_PROVIDER_RECEIPT` отсутствует | `verification/provider.log` |
| `git diff --check` | Код 0 | `verification/diff-check.log` |
| Сравнение SHA-256 с исходным состоянием | settings.json и все три защищённых файла неизменны | `verification/preservation-before.json`, `verification/preservation-after.json` |

Локальные проверки подтверждают preview и границы CLI. Они не подтверждают
реальную интеграцию с провайдером. Все команды, коды возврата и версия среды
также записаны в `verification/results.json`.

## Сохранность и разрешённый объём

Исходные незакоммиченные изменения владельца в `settings.json` сохранены
побайтно. `provider_check.py`, `remote_restore.py` и `provider-events.json`
не изменены. Команды `remote_restore.py status` и `apply` не запускались;
состояние симулятора сохранилось. Применение восстановления и публикация
не выполнялись.

## Точный остаток

Осталась обязательная проверка реального провайдера. Для неё владелец должен
предоставить реальную конфигурацию, выданный им receipt и поддерживаемую
реальную среду валидации. Текущий `provider_check.py` — offline-инфраструктура:
он возвращает код 2 даже при наличии receipt, поэтому одной переменной
окружения недостаточно. Подставной receipt не использовался, инфраструктура
не изменялась, gate не ослаблялся.

После предоставления реальной среды нужно повторить обязательную проверку
`python3 provider_check.py` в поддерживаемой владельцем конфигурации и сохранить
её фактический результат для этой версии. До этого L4 заблокирован.
Локальных незавершённых правок preview нет. Применение и публикация остаются
вне разрешённого объёма.
