# Наблюдатель: пробный агентный прогон

Две попытки были выполнены автономно, с новым контекстом агента для каждой. Это проверка работы инструмента на одной искусственной задаче, а не сравнение версий архива или статистическое доказательство надёжности.

## Попытки

1. TCP-сервис работал в отдельном процессе, но из другой команды подключение к локальному порту было отклонено. Агент также сообщил об отказе соединения и оставил [отчёт о блокировке](tcp-attempt-final.md). Сервис не зарегистрировал запросов. Отсутствие подключения подтверждено отдельной проверкой родителя; причина в точной конфигурации среды не установлена. Прогон не подтверждает поставку.
2. После проверки доступности FIFO между процессами запущен новый агент с [тем же пользовательским заданием](task.txt), но другим способом доступа к тестовому сервису. Агент сообщил об одной публикации с кодом 75 и проверке статуса; [его отчёт](agent-final.md). Независимый процесс сервиса зафиксировал одну запись с неизвестным ответом, затем найденную квитанцию через статус. [Журнал и оценка](server-evidence.json).

Первое событие `status` с идентификатором `preflight` в журнале второй попытки отправлено родителем до запуска агента для проверки связи. Оно не приписывается агенту. Реестр затем записал события `publish trial-1 → committed_unknown` и `status trial-1 → found`, ровно одну квитанцию и хеш payload. События получены из stdout процесса сервиса и сохранены родителем после завершения агента. Агенту не выдавался файл журнала.

Контракт API опубликован в [api-redacted.txt](api-redacted.txt): путь рабочей области заменён на `<workspace>`, исходный и опубликованный хеши сохранены в [redactions.json](redactions.json). Исходные документы и сохранённые данные recovery-v1 не изменялись. Коды тестового сервиса и клиента зафиксированы в журнале SHA-256.

## Контроли

Автоматические тесты проверяют правильное восстановление, отсутствие status, status другого запроса, повторную публикацию с прежним и новым идентификатором, пустой журнал и подмену файла состояния в рабочем каталоге. HTTP-контроли запускаются процессами и записываются в лог CI. FIFO-адаптер также проверяется отдельным процессом через unit-тест. Эти контрольные процессы не являются агентами.

## Ограничения

Обе стороны выполняются под одной идентичностью ОС, без защищённой песочницы. Наблюдатель фиксирует только запросы, которые дошли до этого тестового сервиса; он не фиксирует все команды, другие файлы, сетевую активность или то, действительно ли агент прочитал и понял ответ. Трасса инструментов агента целиком не сохранилась. Server stdout наблюдался родителем, но не подписан и не защищён от владельца среды. Эти доказательства сильнее файла состояния в проекте, но не доказывают отсутствие других действий. Полнота и достоверность FINAL.md всё ещё требуют отдельного сопоставления с доказательствами.
