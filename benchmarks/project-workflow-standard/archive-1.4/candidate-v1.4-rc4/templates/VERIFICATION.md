# Отчёт проверки

Образец. Уровни и статусы определяются в [TESTING-LEVELS.md](../TESTING-LEVELS.md). При переносе рабочей копии поправь относительные ссылки.

## Версия и среда

- Проверяемое изменение и выбранные уровни: не заполнено.
- SHA, рабочий diff либо версия/хеш артефакта: не зафиксированы.
- Среда, версии зависимостей и режим сборки: не зафиксированы.
- Изоляция аккаунтов/данных и внешние зависимости: не описаны.

## Выполнение

| REQ-ID/сценарий (если есть) | Уровень и команда/действия | Результат | Точное доказательство / ограничение |
|---|---|---|---|
| Не определены | Не выбраны | Не выполнено | Доказательства отсутствуют |

Для исправления ошибки укажи воспроизведённый исходный сбой **либо** подтверждённые факты и причину невозможности воспроизведения; затем — результат целевой регрессионной проверки на исправленной версии. Если исходный сбой не воспроизведён, не объявляй его историческую причину устранённой без доказательств и оставь ограничение в итоге. Один успешный запуск не доказывает отсутствие нестабильности; укажи повторения, если они были необходимы и выполнялись.

## Интерфейс — если применимо

- URL/маршрут или способ запуска приложения: не указан.
- Новая сборка, viewport/устройство, тема и способ ввода: не зафиксированы.
- Проверенные экраны, пользовательские действия и защищённые от регрессии сценарии: не перечислены.
- Загрузка, пустое состояние, ошибка и восстановление: не проверены.
- Снимки и факт их просмотра: отсутствуют.
- Реальный backend / подставной ответ; реальное устройство / эмуляция: не определено.

Удалить этот раздел для задачи без интерфейса. Для замера скорости дополнительно фиксировать условия, выборку и сравнимость сборок.

## Решение

- Источник актуальных требований: не указан. Сверить каждый критерий с фактическим доказательством, обновить его состояние в существующем реестре; если реестра нет, перечислить требования и остаток здесь.
- Что подтверждено: не заполнено.
- Что не проверено и почему: не заполнено.
- Блокирующие проблемы или активные разрешённые исключения (`EXC-ID`, область, срок, источник решения): не зафиксированы. Исключение не превращает тест в «успех».
- Следующее действие: не определено.

Перед передачей логов и снимков проверь отсутствие секретов и приватных данных; ссылка должна вести на точный результат. Этот отчёт подтверждает только записанные проверки. Готовность к публикации оценивается отдельно по обязательным правилам проекта.

## Автоматизируемая запись (необязательно)

Один JSON рядом с локальными доказательствами; не включать его в стандарт и не дублировать существующий реестр. При использовании `--record` обязательны поля ниже. Идентификатор кандидата: `git:` + 40 hex либо `sha256:` + 64 hex. Он является заявлением автора записи; хеши доказательств проверяются фактически. Пример входов и регрессионные тесты — в независимом треке аудита, указанном в VALIDATION.md.

| Поле | Значение schema 1 |
|---|---|
| `schema`, `candidate`, `environment` | `1`, точная версия, непустое описание среды |
| `checks` | Массив: уникальный `id`, `level` L1–L5, `kind` static/build/unit/integration/ui/device/ci/delivery, boolean `required`, `candidate`, `status` |
| `status` проверки | pass/fail/not_run/unavailable/not_applicable; для неуспеха нужен `reason` |
| Успешная проверка | `execution: actual`, непустой `command` (или описание действий), непустой `evidence`: объекты `path` относительно записи и `sha256` реального файла. Путь без symlink и выхода за каталог; файл до 2 MiB |
| `requirements` | Уникальный `id`, `status` done/partial/blocked/excluded/not_assessed/in_progress, `checks`: ID проверок. Для done все связанные проверки успешны; для excluded — `approval` с источником решения владельца; для остальных — `reason` |
| `exceptions` | По умолчанию пусто. Используемая EXC: `id`, `check`, `candidate`, `environment`, `status: active`, `approved_by`, `approval`, `reason`, `risk`, `compensation`, `expires` с часовым поясом. EXC не меняет статус проверки |
| `l4` | Boolean. true требует закрытых обязательных gates и всех требований done/excluded. Неприменимость сама не закрывает обязательный gate |
| `claims` | Необязательный массив device_tested/ui_tested/ci_executed; каждому нужен успешный фактический check соответствующего kind. Классификацию задаёт автор; утилита её подлинность не устанавливает |
| `delivery` | `status`: not_started/prepared/published/verified/failed/recovery_required. Для published/verified нужны `permission` с источником, `candidate` текущей версии и l4=true; для verified дополнительно успешная L5 kind=delivery |

Запись не даёт разрешения выполнить внешнее действие. Самостоятельно выставленные `approved_by`/`permission` не заменяют проверку источника агентом/рецензентом. Отсутствующий обязательный тест нельзя скрыть, убрав его из JSON: полноту gates проверяют по конфигурации проекта. Хеш журнала доказывает его целостность относительно записи, не факт исполнения.
