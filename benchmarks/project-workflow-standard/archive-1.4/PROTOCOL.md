# PWS-ARCHIVE-1 — зафиксированный протокол

Предмет: валидаторы самостоятельного 16-файлового архива. Уточнение владельца исключило проверку приложения. Это не запуск Control/v1.3/rc3/rc4 ИИ-агентов и не испытание качества Android/UI. Старый Protocol 1.2 со своими требованиями Docker/attestation не используется для объявления accepted agent runs и не ослабляется.

Режимы: CRC-only (библиотека zipfile; только контроль целостности), reviewed checker rc3, reviewed checker rc4. Для каждого checker берётся его неизменный исходный комплект, вносится одна логическая мутация. Версии текстов/скриптов различаются намеренно: сравниваются инструменты проверки собственных версий, а не ответы модели на одинаковый prompt. v1.3 сохранён, но не содержит executable checker; его автоматический результат N/A. CRC-only не является «Control — ИИ без стандарта».

Корпус фиксируется списком CASES в compare_archives.py. Положительные входы: корректные ZIP/каталог, иллюстративная ссылка внутри fenced code. Отрицательные: потерянный файл, лишний payload, invalid UTF-8, сломанная inline/image/reference/anchor-ссылка, утрата защитного маркера, пустой README, неверная версия, ZIP symlink, directory symlink, нерегулярный файл, неоднозначные/выходящие пути, duplicate entry, oversized source/ZIP, синтаксическая ошибка Python, обход через python -O, отдельные повреждения CRC. Каждой проверке заранее назначено expected_accept. Обязательная проверка каждой мутации: действительно отличается от базового ввода.

Порядок детерминирован: case → repeat 1..3 → CRC/rc3/rc4. Время — wall clock subprocess/CRC целиком через perf_counter; среда фиксируется фактически. Три повтора только для устойчивости инструмента, не независимые статистические AI-наблюдения. Успешный отрицательный контроль — валидатор вернул ровно exit 1; traceback/timeout/другой exit — ошибка инструмента, даже если ненулевой код. Подтверждённое улучшение: rc4 обнаруживает все предписанные отрицательные входы, принимает положительные и не ухудшает совпадающие защитные проверки rc3. Отдельно считать false_accept, false_reject, tool_error; качество не компенсируется временем. Статистическое превосходство поведения ИИ не выводить.

Сохранить все outcomes, exit/status, stdout/stderr с редактированными только временными путями, хеш точных входных ZIP и файлов, хеш checker, платформу/Python, elapsed. Для ZIP с symlink хешировать содержимое записи, не её цель. Для каталога symlink/FIFO фиксировать тип и synthetic target. Код корпуса/evaluator хешируется в RESULTS.json; при изменении критериев после первого измерения — новая версия протокола и отдельный набор результатов.

Регрессионный unittest-набор дополнительно проверяет opt-in schema 1 и девять типов ложных утверждений о проверке/поставке. Это проверки инвариантов записей, не тесты выполнения реальных задач. Время/токены/стоимость/лишние действия агентов и успех после настоящей потери контекста — не измерены. Положительные JSON-примеры с синтетическим логом служат контролями валидатора и никогда не публикуются как свидетельство исполнения приложения.

Фиксация: этот документ и compare_archives.py коммитятся до первого сравнительного запуска. Корпус выбран по аудиту, поэтому это регрессионная выборка с известными дефектами, не held-out оценка общей способности обнаруживать новые ошибки. Независимый review кода дополняет её.
