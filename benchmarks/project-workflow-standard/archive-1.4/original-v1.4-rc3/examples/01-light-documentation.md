# Пример 1 — небольшая правка документации (Light)

> Вымышленный пример, не реальная выполненная работа.

**Цель:** исправить неверное описание параметра в разделе помощи. **Границы:** только документация; синтаксис команды не изменять. **Существующий контракт:** установленное поведение CLI и другие разделы не менять.

**Запись в задаче вместо PLAN.md:** «Исправить описание ключа; критерий готовности — оно совпадает с текущим `--help`, внутренние ссылки ведут на существующие разделы».

**Проверка:** L1 — сопоставить текст с фактическим `--help` и пройти по изменённым ссылкам. Если программа для сравнения недоступна, указать это и не объявлять сопоставление успешным. L2–L5 без дополнительных причин **не требуются**.

**Финал после действительно выполненной работы должен содержать:** что исправлено, конкретную ревизию/файл, реально исполненные проверки и их результат. Если проверка выполнена только чтением, так и назвать. Не создавать REQ-ID, PR или отдельный отчёт без потребности.
