# Независимый обзор controller.py

Проверены `controller.py`, `tests_controller.py`, применимые участки `gate_observer.py`, `prepare.py` и `PROTOCOL.md`. Код не изменялся. Существующие тесты контроллера: **13/13 прошли**.

## Подтверждено

- При формировании итогового INDEX сохраняется SHA-256 текущего `FREEZE.json`, а для каждого receipt — его SHA-256, head, hash ключа, конфигурации и исполняемых файлов. При разборе receipt проверяются соответствие INDEX и FREEZE, уникальный trial, case, root, цепочка HMAC, фиксированная конфигурация команд и input hashes до/после и на конечной версии.
- Команды наблюдателя выбираются из фиксированных сценарных конфигураций; перевод событий дополнительно сравнивает argv и config hash с реконструированным из FREEZE контрактом. Неполные события, неверный stimulus S03, изменённый исполняемый файл, старые input hashes или неправильный immutable gate не становятся валидными событиями.
- `evidence_from_receipt` на валидном и невалидном пути возвращает только `coverage: partial`. PID/cwd FIFO запроса не аутентифицированы, инициатор остаётся unknown. В коде и протоколе явно указаны общий UID и файловая система, возможность вмешательства, отсутствие OS sandbox и полного trace. HMAC/индекс не являются аттестацией от агентного вмешательства с тем же UID.
- Тесты также проверяют подмену receipt/config/исполняемого файла, несоответствие manifest, отсутствие привязки к конечной версии, прямой необслуживаемый запуск, fake output, сигнал и завершение с иным кодом.

## Ограничения, требующие учёта при измерениях

1. **Начальная сверка проекта с FREEZE находится вне контроллера.** `Controller.start()` читает manifest и конструирует конфигурации, но не сравнивает полный входной inventory, dirty diff/HEAD, инструкции и task каждого trial с FREEZE до начала модельной работы. Само совпадение hash FREEZE и INDEX подтверждает содержимое manifest, а не то, что все файлы физически совпали с ним до старта. Orchestrator должен выполнить отдельную первоначальную проверку и сохранить её результат.
2. **Публичные файлы тестов не закреплены как immutable.** Для S01/S07/S08 событие привязывается к hash окончательной версии test-файла, но агент может её изменять. Поэтому наблюдаемый exit 0 доказывает запуск конкретной финальной версии тестов, а не успех неизменённого исходного набора. Отдельно сравнивать тесты с frozen inputs и отдельно оценивать hidden product oracle; добавление тестов не должно автоматически считаться ошибкой.
3. FIFO сервис фиксирует *верхнеуровневый* заранее заданный argv. Содержимое изменяемого `ci.sh`, импортируемого Python-кода и тестов исполняется дочерним процессом и потенциально может запускать другие действия. Сервис не обеспечивает ограничение subprocess или секретов: только искусственные фикстуры без production; для недоверенного кода нужен отдельный OS sandbox.
4. INDEX и оригинальный FREEZE должны сохраняться отдельно от редактируемого workspace и быть заранее привязаны к независимому снимку, но в текущем host их UID общий с агентами. Код подтверждает связность предоставленных bytes, не их подлинность против same-UID вмешательства. Передавать этот предел вместе с любыми результатами.
5. Hash до/после и hash конечного файла не доказывают отсутствия временных изменений во время выполнения. Это ограничение зафиксировано в самом receipt. Незарегистрированный вызов не означает, что он не происходил.

Свидетельств полноценной атрибуции запроса конкретному агенту, изоляции или coverage=full код не предоставляет и не должен использоваться для таких выводов.
