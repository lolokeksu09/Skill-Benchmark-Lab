# Второй этап: локальный DDS 2.0.5 Web-пилот

Этот сценарий сравнивает Web-исправления **контрольного режима** с режимом **Development & Design Skills 2.0.5** на одной локальной модели. Режим DDS не подменяется написанной вручную подсказкой: программа сверяет SHA-256 полного архива с `benchmarks/versions.json` и читает из ZIP **оригинальные** инструкции `SKILL.md`.

Пропорционально задаче активированы **две** инструкции:
- `systematic-debugging/SKILL.md`: владелец процесса исправления воспроизводимой ошибки;
- `accessibility-compliance-accessibility-audit/SKILL.md`: специалист по доступности кнопки.

Это испытание **маршрутизированного набора из двух Skills**, не загрузка всех 116 навыков одновременно и не тест качества маршрутизатора. Сам ZIP не публикуется в репозитории. Все активные имена и контрольные хэши отдельных текстов сохраняются в результате. Исходное пользовательское задание и тестовый Web-стенд совпадают с `control`; изменяются системные инструкции, как и предусмотрено экспериментом. Полный режим и P2P ещё не выполнены.

## Действия на Android

1. Скачать проверенный архив `Development-Design-Skills-2.0.5-Full-Patched.zip` в стандартную папку **Download**. Не распаковывать.
2. В **уже установленной** папке лаборатории Termux:

```bash
cd "$HOME/Skill-Benchmark-Lab" && git pull --ff-only && python -m evaluator.development_pilot --preview
```

Предпросмотр только подтверждает ZIP и показывает выбранные навыки, не обращаясь к нейросети. Программа автоматически проверяет оба стандартных пути: `~/storage/downloads/Development-Design-Skills-2.0.5-Full-Patched.zip` и `/storage/emulated/0/Download/Development-Design-Skills-2.0.5-Full-Patched.zip`. Если Termux не имеет доступа к Downloads, сначала нужно разрешить доступ через `termux-setup-storage`. Можно указать альтернативное местоположение `--archive /путь/к/файлу.zip`.

Следующий запуск после успешной проверки:

```bash
python -m evaluator.development_pilot --repeats 1 --max-tokens 400
```

При работающем `llama-server` на `127.0.0.1:8080` программа запишет реальное время, токены, исходный JSON и **отдельную статическую оценку** в `results/raw/local-qwen-web-development.jsonl`. Вывод JavaScript не исполняется. Существующие результаты/кандидаты не перезаписываются.

### Ограничения точности

- Контекст серверной модели сейчас 2048 токенов. Полные файлы двух навыков увеличивают размер запроса и могут не поместиться. Если сервер вернёт ошибку контекста, пробный результат учитывается как ошибка; **нельзя незаметно увеличивать контекст только для DDS** и затем сравнивать с контрольным запуском. Нужно повторить обе серии при одном новом лимите.
- Нельзя сопоставлять скорости без учёта заметно разной длины входного контекста: сохранять `prompt_tokens`, `completion_tokens` и время отдельно.
- Три контрольно-сохранённых ответа имеют одинаковую статическую оценку, но это **не доказывает одинаковый текст** или одинаковый результат Node-тестов.
