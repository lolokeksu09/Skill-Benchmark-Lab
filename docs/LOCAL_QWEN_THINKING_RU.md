# Режим Thinking: новое двухплечевое испытание Qwen3-8B

Запускаются те же файлы и критерии Web-сценария, но с директивой `/think` вместо `/no_think`.

- `control` — без Skills.
- `development` — оригинальные инструкции двух навыков из SHA-256-проверенного ZIP DDS 2.0.5.

В обоих режимах одинаковая температура `0.2`, `max_tokens=768`, контекст текущего сервера 2048 и одна модель. Для DDS входной запрос длиннее, что влияет на длительность. Новая серия не подменяет четыре старых измерения. Необходимы отдельные повторные прогоны для устойчивых выводов.

## Один шаг в Termux (сначала контроль)

```bash
cd "$HOME/Skill-Benchmark-Lab" && git pull --ff-only && python -m evaluator.thinking_pilot --variant control
```

Затем (после просмотра результата) второй режим:

```bash
python -m evaluator.thinking_pilot --variant development
```

Сохраняется JSONL `results/raw/local-qwen-web-thinking-{control,development}.jsonl`, сырой ответ API вместе с reasoning и итоговый кандидат отдельно под `results/raw/local-qwen-web-candidates/thinking/`. Сгенерированный JavaScript **не исполняется**. Если генерация обрезана по `finish_reason=length`, это неуспешный кандидат. Отсутствие `reasoning_present` не доказывает, что сервер не использовал Thinking: конкретная версия API может не отдавать его явно.

Если превышен лимит контекста, ошибка фиксируется — нельзя менять лимит лишь для одного режима и считать их сравнимыми.

## Фактический результат Thinking Control 001 (25 октября 2026)

Контрольный Thinking-запуск достиг лимита `768/768` выходных токенов без корректного JSON и без проверяемого кода: `205.495` секунд, `254` входных токена, `1022` токена всего, `finish_reason=length`, `reasoning_present=true`. Это **неудачный эксперимент**, не улучшение и не повод без проверки увеличить лимит только у контроля.

**Исторический статус:** до подтверждения поддержки бюджета DDS Thinking не запускался. Для полноценного A/B нужно сначала подтвердить наличие механизма ограниченного thinking в *установленной на Termux* версии `llama-server`. Актуальная документация llama.cpp описывает `--reasoning-budget`, но наличие этого флага в локальной версии не проверено.

Проверка возможностей (не влияет на работающий сервер):

```sh
llama-server --help 2>&1 | grep -E -A 2 -- 'reasoning-budget|reasoning-effort' || echo 'Budget flags not advertised'
```

После реального подтверждения параметров сервера готовить отдельно новый эксперимент с одинаковым ограничением reasoning и output для обеих групп, без изменения сохранённых измерений.

## Контрольный запуск с ограниченным Thinking: trial-002

Пользователь проверил наличие `--reasoning-budget N` в своей сборке `llama-server`, перезапустил модель с `--reasoning-budget 128` и получил нормальный ответ от HTTP API.

`thinking/control/trial-002`: 76.762 с, 254 входных + 271 выходной токен (525 всего), `finish_reason=stop`, `reasoning_present=true`. Статическая проверка: `pass=1`, `fail=1`, `uncertain=1` (HTML экранирование возможно верное, но Node не запускался). Предыдущий неограниченный запуск `trial-001` завершился по лимиту `768` токенов без JSON.

Для парного режима DDS требуется **тот же запущенный сервер с бюджетом 128 и контекстом 2048**, одинаковый `max_tokens=768`:

```sh
cd "$HOME/Skill-Benchmark-Lab" && git pull --ff-only && python -m evaluator.thinking_pilot --variant development --max-tokens 768
```

DDS включает только два профильных оригинальных `SKILL.md` из проверенного архива. Результат `static_preflight` — предварительный, не runtime тест.
