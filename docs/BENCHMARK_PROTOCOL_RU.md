# Skill Benchmark Lab v2 — протокол без платного API

**Цель:** сравнить влияние оригинальных навыков P2P и Development & Design Skills на исправление кода **одной сильной моделью** в Codex Cloud. Модель не меняется между вариантами.

**Базовая ветка:** `bench/v2-strong-base`. **Задача:** `TASK.md`. Исходное состояние: 1/8 Node тестов. Эталон исправления не публикуется. **Запрещено** переносить результаты старого Qwen-пилота в текущие испытания.

## Пять режимов

1. `control`: только базовое задание; никаких дополнительных P2P/DDS.
2. `p2p-original`: оригинальный P2P 9 с реальной загрузкой инструкций.
3. `p2p-improved`: улучшенный P2P 9 с реальной загрузкой инструкций.
4. `development`: оригинальные актуальные SKILL.md из DDS 2.0.5 Full Patched, выбираемые по задаче.
5. `combined`: P2P Improved формирует промпт, а DDS применяется при исполнении.

Архивы Skills **не включать в публичный GitHub**. Проверять их реальные SHA-256 перед запуском:

| Архив | SHA-256 |
|---|---|
| P2P Original | `daee2df26f09c7b9bd0b11a5af4675c738dd119a7c8da0744c1e55c226bd23a8` |
| P2P Improved | `b4162a2c6118a4f12bbbd1bcc0d6acd5311c671cce56e3ff58f158722ef0f1d5` |
| DDS 2.0.5 Full Patched | `c6fe56e96644ae30b8ba07c35cd6a52a5a7ad34920558923ea1c947023db3439` |

**Нельзя симулировать Skills по названиям.** Для каждого варианта зафиксировать реально прочитанные инструкции, версию ZIP и способ их передачи модели. P2P — процедура создания промпта, а не вручную придуманное улучшение от испытателя.

## Независимые прогоны

В идеале: 5 режимов × 3 независимых запуска = 15 задач. Сначала пилот `control-001` и `development-001`, чтобы подтвердить доступность Codex, инструменты и корректность включения навыков.

Каждая задача: новая сессия/рабочая область, **строго один начальный commit SHA** базовой ветки, одна выбранная модель, один уровень reasoning, один TASK.md, Node 22, одинаковый доступ к инструментам. Никакой истории предыдущих ответов. Результат — отдельная ветка/PR; базу не менять.

## Что измеряем

- Число пройденных из 8 фактически выполненных Node тестов, код возврата; нарушения ограничений TASK.md.
- Слепая проверка качества/минимальности изменений (без названия варианта).
- Время и токены — только если среда реально сообщает; иначе `null`. Не выдавать подписочные usage-лимиты за токены API.
- SHA base/head, выбранную модель, reasoning, номер trial, SHA архива, прочитанные SKILL.md, дифф и сообщение CI.

Тесты доступны самой модели — это **открытый** функциональный бенчмарк, не скрытый holdout. По одному пилоту нельзя доказать преимущество Skills. Запрещено редактировать тесты, пакетные сценарии и workflow. GitHub Actions сверяет SHA задания и тестов.

## Без дополнительных платежей

Использовать только включённый лимит ChatGPT Plus в Codex Cloud; API-ключи, кредиты, пополнения и внешний платный inference — запрещены. При исчерпании квоты прервать эксперимент до её восстановления. Codex Cloud первоначально требует создать и опубликовать среду на вебе/десктопе, затем можно работать с телефона.

Нельзя утверждать, что Work/Codex гарантирует программное назначение одной модели или точный учёт токенов: если нужные настройки недоступны, это ограничение отчёта. Если исходные ZIP Skills не доступны Codex Cloud, настроить их доступ или использовать одно и то же альтернативное окружение для **всех** пяти вариантов; смешивать платформы нельзя.
