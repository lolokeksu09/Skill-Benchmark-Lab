# Первый Control-тест в Codex Cloud

Создать и опубликовать среду для `lolokeksu09/Skill-Benchmark-Lab` в Codex Cloud через веб/десктоп (Node.js >=20). Выбрать `bench/v2-strong-base`, **не** `main` и **не** старые Qwen-ветки. На мобильном затем открыть опубликованную среду.

Выбрать одну доступную сильную модель для программирования, например GPT-6.1 Sol, зафиксировать её название и reasoning-настройку. Использовать тот же вариант модели во всех последующих испытаниях.

## Текст для отдельной задачи Control Trial 001

> В `lolokeksu09/Skill-Benchmark-Lab`, исходная ветка `bench/v2-strong-base`, выполни `TASK.md` как независимый **Control Trial 001**. Не подключай P2P, DDS или другие Skill-пакеты. Не ищи ответы, решения и историю в других ветках/PR. Меняй только `src/board.mjs` и `src/board.css`. Запусти `npm test`, сохрани результат в отдельной ветке и предложи PR без слияния. Верни название модели и reasoning-настройку, начальный SHA, фактические тесты (код возврата и passed/failed), SHA итогового коммита и краткий отчёт о правках. Если что-либо недоступно — явно отметь это.

**После Control:** отдельный новый запуск DDS должен получить *точно тот же исходный коммит*; набор SKILL.md должен быть реально доступен и проверен SHA. Без этого считать режим DDS непроверенным, а не проигравшим.
